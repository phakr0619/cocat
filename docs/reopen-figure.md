# スライドに貼った図を、Cocat で開き直す（2026-11-08、ユーザーと決めた）

## 目的

PowerPoint などに貼った Cocat の図を、あとで Cocat で開き直して直せるようにする。ChemDraw を持っていなくても直せることがいちばん大事（ChemDraw の埋め込み（OLE）は、ChemDraw の無い環境では確かめられないので保留）。

ブラウザのアプリは、PowerPoint で図をダブルクリックしたときに呼び出してもらう仕組み（OLE）に入れない。そこで、**図の画像（PNG）の中に Cocat のデータを目に見えない形で入れておき、Cocat で pptx（または PNG）を開くと、その図を編集できる状態に戻す**形にする。PowerPoint のアドイン（図を選んでボタンで Cocat を開く）は、これを土台にして後で考える。

## 確かめたこと（2026-11-08、ユーザーの PowerPoint で）

データを入れた PNG と SVG を作り、PowerPoint に入れて保存した pptx の中で、データが残るかを確かめた（確かめる道具は、ブラウザの中だけで pptx を読むページ）。

| 貼り方 | デスクトップ版 | ウェブ版 |
| --- | --- | --- |
| PNG をファイルから挿入 | 残る（1798×953 px のまま、圧縮もされない） | 残る |
| SVG をファイルから挿入 | **消える**（PowerPoint が書き直す。21 KB → 14 KB） | 残る |
| PNG ファイルを Edge で開き「画像をコピー」→ 貼り付け | 残る | — |
| ページの中の画像（blob: の URL）を右クリック →「画像をコピー」 | **消える** | — |
| ページの中の画像をスライドへドラッグ | 残る | — |
| ページから `navigator.clipboard.write` で PNG だけを置く（今の Cocat の「コピー」） | **消える**（ブラウザが画像を作り直す。この環境の Chromium でも、読み戻した PNG にデータが無かった） | — |
| 同じく、画像を中に含む HTML（`<img src="data:image/png;base64,…">`）を置く | 残る | — |
| HTML ＋ PNG ＋ 文字（SMILES）を一緒に置く | 残る（PowerPoint は HTML の画像を使う） | — |
| PowerPoint の「図として保存」で取り出した画像 | **消える**（960×508 に描き直される） | — |

- PowerPoint は、同じ中身の画像を pptx の中で 1 つにまとめて持つ（スライド 2・3 が同じ画像を使う、など）
- 分かったこと: **PNG に入れれば、ファイルからの挿入・ドラッグ・Cocat のコピー（HTML を足せば）のどれでも残る**。開き直すときは、図として保存した画像ではなく、**pptx そのもの**を Cocat で開く

## 形

### PNG の中のデータ

- PNG の `iTXt` の塊。キーワードは `cocat`、zlib で圧縮、中身は `.acedoc` と同じ JSON（`serializeDoc`、版の番号つき）。IHDR のすぐ後に置く
- 画像の見た目は変わらない。大きさは、3 段のスキームで約 4 KB 増える（圧縮した JSON）

### 入れるデータ（決めたこと #2 の A）

コピーした部分（`extract` の結果）は、文書のスキーム・化合物・検討表・書式をすべて持ったままなので、図に描いてある物に関わる分だけに絞る。

- **スキーム・検討表**: 図の中の原子（`ref` の「スキーム id:化合物 id」）・矢印・文字・＋（`ref` のスキーム id・表の id）が指すものだけを残す。ただし、そのスキーム（表）が描いた物の**一部だけ**をコピーしたときは、データを残さない（残すと、描いていない化合物の構造まで入るため）。その図はただの絵として入り、開き直すとスキームのデータの無い図になる
- **化合物**: 残したスキーム・表が使う化合物だけ
- **書式**: 残したスキーム・表が使う書式だけ
- **略号の辞書**: 図の中で使っている略号だけ
- **入れない**: 化合物のメモ（`note`、図に描かない）、ライブラリとのつながり（原子の `lib`）、段の実験の量（`scale`・`substrateEquiv`、化学量論表だけに使う）、AI に送った文章（下書きの `draft.text`）
- **入れる**: 図に描いてあるもの（構造・条件・番号・呼び名・ノート番号（書式で描くとき）・収率）と、開き直すと同じ図になるのに要るもの（書式・ページの設定・線の太さ）

### コピー

`writeSystemClipboard` が置くものを次の 3 つにする。

| 形 | 中身 | 使うアプリ |
| --- | --- | --- |
| `text/html` | `<img src="data:image/png;base64,…">`（データ入りの PNG） | PowerPoint・Word など |
| `image/png` | データ入りの PNG（ブラウザが作り直すので、貼った先ではデータは消える） | HTML を受け付けないアプリ |
| `text/plain` | SMILES（今までどおり） | テキスト・ほかの構造式エディタ |

### PNG の書き出し

書き出す PNG にも、文書全体（から上の範囲に絞ったもの）を入れる。

### 開き直す

- 「読み込み」の「ファイルを開く」で、`.pptx` と `.png` も選べるようにする
- **pptx**: 中の画像（`ppt/media/`）から Cocat のデータが入った PNG を探す。どのスライドで使っているかを、スライドの関係（`ppt/slides/_rels/slideN.xml.rels`）から読む
  - 1 つだけなら、すぐ開く
  - 2 つ以上なら、「スライドの図を選ぶ」画面に、図の小さな絵とスライドの番号を並べ、選んだものを開く
  - 無ければ「この pptx には、Cocat で作った図が見つかりませんでした。Cocat からコピーして貼った図か、Cocat で書き出した PNG を挿入した図だけを開けます（『図として保存』した画像からは開けません）」
- **png**: データがあれば開く。無ければ同じ理由を出す
- 開くと、`.acedoc` を開いたときと同じく今の文書と置き換える（元に戻すで戻せる）。ファイルの名前は「元の pptx の名前 スライド 3」
- zip の読み込みは自前（中央ディレクトリを読み、圧縮は `DecompressionStream('deflate-raw')`）。pptx の中のほかのファイル（文字・ほかの画像）は読まない。どこにも送らない
- Word（docx）も中の形は同じ（`word/media/`）だが、Word に貼ったときにデータが残るかは確かめていないので、まずは pptx だけ

## テスト

- ユニット: PNG にデータを入れて読み戻せる（見た目の画素は変わらない）。入れるデータの絞り方（一部だけのスキームはデータを残さない、メモ・ライブラリ・量・AI に送った文章を入れない、使う略号・書式だけ）。pptx（テストで作るもの）からスライドの番号つきで図を見つける（同じ画像を 2 枚のスライドで使う場合も）。データの無い PNG・pptx
- E2E: コピーでクリップボードに HTML・PNG・SMILES が置かれ、HTML の中の PNG からデータを読める。PNG を書き出して開き直すと同じ図になる。pptx を開くと選ぶ画面が出て、選んだ図が開く。データの無い pptx は理由を出す
- 手で: ユーザーの PowerPoint で、Cocat からコピーして貼った pptx を開き直せること
